Por qué cada prompt tiene 5 partes

La teoría completa está en las láminas — esto es el resumen que te queda a mano. Cada prompt de esta guía (Paso 1 a 5) sigue siempre la misma estructura:

1. CONTEXTO
Qué código es y qué archivos ya existen (REGLAS.md, RETO.md...).
2. OBJETIVO
Qué archivo tiene que producir la IA al terminar.
3. RESTRICCIONES
Qué no debe tocar o asumir.
4. CRITERIOS
Cómo se sabe que el resultado está completo.
5. FORMATO
La estructura exacta del archivo de salida.

Si la respuesta no es lo que esperabas, no repitas el mismo prompt: ajústalo agregando la parte que faltó (un ejemplo, una restricción, el archivo que ignoró). Esa es toda la "iteración" — mejorar el prompt según lo que salió mal, no el código a mano.

02refactor
Paso 2

Corregir hallazgos, plan antes de código

Tú eliges el alcance: prioriza los 2-3 de mayor severidad si el tiempo apremia, o resuélvelos todos si te alcanza.

45-60 min

Ojo con el nombre: este paso corrige cualquier tipo de hallazgo pendiente (Vulnerabilidad, Bug, Refactor o Sugerencia), no solo los que tienen "Refactor" en la columna Tipo de HALLAZGOS.md. "Refactor" aquí es el nombre de la sesión, no un filtro.

Cómo clasificar cada hallazgo, antes de elegir

Para cada fila de HALLAZGOS.md, pregúntate estas dos cosas por separado:

Impacto — ¿qué tan grave es si pasa?
  • Alto: expone contraseñas/datos personales, o deja que alguien cambie o borre datos de otro usuario.
  • Medio: rompe una funcionalidad, pero no expone datos sensibles.
  • Bajo: es un detalle de estilo o legibilidad — no afecta seguridad ni funcionamiento.
Probabilidad — ¿qué tan fácil es que pase?
  • Alta: no requiere saber nada especial — cambiar un valor en la URL o el formulario alcanza.
  • Media: requiere algo de intención técnica, como leer el código o armar un request a mano.
  • Baja: requiere acceso privilegiado o condiciones muy específicas.
Cruza los dos valores en esta tabla
Prob. bajaProb. mediaProb. alta
Impacto altoMedioAltoCrítico
Impacto medioBajoMedioAlto
Impacto bajoBajoBajoMedio
Ejemplos ya clasificados
  • "Un usuario puede consultar tareas de otro cambiando un parámetro" → impacto alto (ve datos ajenos) + probabilidad alta (solo cambiar un valor) = Crítico, se resuelve primero.
  • "SQL concatenado" → impacto alto + probabilidad media (hay que saber armar el input) = Alto.
